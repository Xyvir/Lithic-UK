# Lithic agent round log: 2026-11

One bullet per round, newest last, written by whoever (or whatever) did the round. **Append the next round here, to the file named for its month, and not to `agents.md`.**

- **A book that keeps its chapters inside one document imports as chapters now, because the table of contents' own points are where a page is cut (2026-11-02):** reported from *Who Goes There?*, which landed as one Favorites row with 556 nodes stacked under it, where the sample book gives sixty-eight chapters. **What made it different is its shape, not a fault:** the file is nine zip entries with a single spine document, 305 KB of `untitled.html` holding the whole novella, and a table of contents whose thirteen points name fragments of that one file (`untitled.html#navPoint_2`). The importer gave a chapter to a spine document, so a book with one document had one chapter however many parts it declared. The generator line says why: `Aspose.Words for .NET 10.2.0.0`, a 2012 Word conversion, which writes a word processor document out as one XHTML file with an `h1` for the title and an `h2` for each of the twelve sections `I.` to `XII.`. **A second cause was hiding behind the first, and it would have kept the fix from working:** `resolveHref` drops a `#fragment` before it resolves, so all thirteen points landed on the same key and `readNav`'s first-name-wins guard kept `Who Goes There?` and discarded the other twelve. `resolveTarget` now returns both halves, `readNav` answers `{labels, anchors}` (labels naming a page, anchors keeping the places a page is pointed into, in the book's own order), and the whole-file naming rule is unchanged. **The cut is made in the block reader rather than in a second pass:** `readBlocks` takes the anchor ids it should watch for and marks the block each one lands on, and marks the block a heading produced, carrying either mark to the next block because a converter often puts the mark on an element of its own and the words after it. `splitPage` then cuts the page at those marks, one chapter per mark, folding whatever precedes the first mark into the first chapter, because a title page, an epigraph and a contents page all sit at the front of a book and none of them is a chapter. **The heading fallback is deliberately narrow:** it engages only when a page has no points to cut at *and* the book is a single document, since a book split into files has said where its chapters are and its own headings are what is inside one. Applying it to every page would have split each of the sample book's sixty-eight chapters at its `h2` subsections, which is a regression dressed as an improvement. A section whose blocks are all pictures the wiki cannot draw is not written at all, and an ordinary book's unnamed page keeps the name it had, because the place in that name is still the spine index when nothing was split. **Evidence, run rather than inferred:** the book imports as thirteen chapters, `Who Goes There?` then `I.` to `XII.`, each Favorite with the code `WGT` as a tag, the first Dogear, the `prev`/`next` chain unbroken, and the 556 nodes distributed across them (twenty-one under the title page, the rest by section); a copy with the NCX emptied still yields thirteen chapters, named from the headings, which is the fallback proven; a copy whose points name ids the document does not have yields the same thirteen without crashing and without a title leaking markup; the sample book is unchanged at sixty-eight chapters and 1760 nodes; and `node scripts/build-library.mjs` writes its twenty-one files, which is the check that catches a module that will not evaluate. **A chapter named by its place is a chapter but not a Favorite, which is the second half of the round and a different complaint:** the sample book's cover and one interior page have no name of their own, so they carried the code in front of them (`IYSS_Page_001`, `IYSS_Page_055`), and seeing that in the sidebar beside `Chapter 1: Foundations` settled it, because a bookmark is read as a name rather than as a filing decision. `chapterTags` now takes whether the chapter has a name and writes the Favorite tag only when it does, `favoriteOrder` writes only those titles into the tag tiddler's list, and `chapters` carries that flag. What the page keeps is everything that makes it a chapter: the code tag, its place under its parent, its `prev`/`next` neighbours and its `stream-list`, so the book still reads through it and `[tag[IYSS]]` still finds it. The sample book goes from sixty-eight favorites to sixty-six with its 1760 nodes and its Dogear unchanged, and the book this round is about is unaffected at thirteen, since every one of its parts has a name. **Left open, deliberate:** a book whose every page is unnamed now contributes nothing to the sidebar at all, which is the honest consequence of this rule rather than an oversight, since there is no name to list and the book is still reachable by its tag; a book imported before this round keeps the one-chapter shape it was written with, because nothing reads a stored book back through the converter; two points naming the same place are one point, which is the honest rule for a part and its first section sharing an address; a single-document book whose headings are subsections rather than parts is now split at those subsections, which is the fallback's own risk and the one shape a reviewer should look at; and `src/lithic.html` is CI built, so a shipped wiki gains the split with the next release.
